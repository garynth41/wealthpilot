# WealthPilot

Personal budgeting, savings and financial-planning app — a stand-alone spin-off of the money modules of CareerShift, rebuilt as a modern Vite + React + TypeScript single-page app on its own Supabase project. (Formerly "PocketLedger"; the Supabase project keeps that name in the dashboard.)

## Brand

- **Design direction: "Graphite"** — Swiss minimal. Cool grey ground, white panels separated by 1px hairlines, almost no radius, one tangerine accent reserved for the primary action, links, the low point and anything overdue; green for good. Headings and large figures in **Space Grotesk**, body in **IBM Plex Sans**, dates and amounts in **IBM Plex Mono** (Google Fonts, loaded in `index.html`). Chosen from the round-2 canvas https://claude.ai/artifact/MUVSiv13RZi5VeargjLmeK (round 1, including the earlier Ledger look, is at https://claude.ai/artifact/GJoDXePjQz4qqYKfQZvG6A). Deliberately *not* the same theme as Gary's other apps.
- **Mark:** a rising course line ending in a tangerine "pilot" arrowhead on a graphite tile — `src/components/Logo.tsx` (in-app) and `public/favicon.svg` (favicon; `public/icon-*.png` and `apple-touch-icon.png` are rendered from the same glyph). Change the glyph in all places together.
- **Theme tokens** (`src/styles.css` `:root` light / `:root[data-theme="dark"]`): ground `#eceef1`, surface white, hairline `--line #d7dbe0`, ink `#15181c`, accent `--accent #c2410c` (tangerine; `--gold #f97316` is the bright form for the mark and chart accent), `--sel` / `--on-sel` for selected states (ink on white), `--good #15803d`, `--warn #b45309`, `--crit #c2410c`, `--info #3b5a8c`. Dark mode is "Graphite night": `#0f1114` ground, `#171a1e` panels, the same hairlines, tangerine lifted to `#f97316` with dark text on it. Every `--x` has an `--x-soft` (fill) and `--x-ink` (text on that fill) that passes the 4.5:1 guard in `e2e/smoke.mjs`.
- Rename again: `VITE_APP_NAME` in `.env`/`.env.example`, the fallback in `src/app/config.ts` (and its `LS` storage-key prefix), `<title>`/`theme-color` in `index.html`, `name` in `package.json`, `setup.ps1`, this README and `HANDOFF.md`.

## Stack

- **Front end:** Vite 8, React 19, TypeScript 7, react-router (hash routing → works on GitHub Pages), zustand store, Plotly (basic bundle) for charts, IBM Plex fonts.
- **Back end:** Supabase (Postgres + Auth + Realtime). Project **pocketledger** (`dshswfcpovdpxcidolqb`, us-east-1). Schema in `supabase/migrations/` — 19 tables (`0001_init.sql` + `0002_holdings.sql`), RLS on every one through `is_member / can_edit / is_owner`, audit trigger (`activity_log`), server-assigned human refs (`A-001`, `T-042`, …), RPCs `create_household`, `accept_invites`, `start_period`.
- **Offline demo:** the same app with an in-memory/localStorage repo and realistic sample data — used by the test suites and as a try-before-sign-up mode.

## Run it

```bash
cp .env.example .env        # already points at the pocketledger Supabase project
npm install
npm run dev                 # http://localhost:5173
```

Scripts: `npm run typecheck` · `npm test` (71 unit tests: engines, intelligence, import, rules, planning, portfolio, retirement, email parser) · `npm run build` · `npm run e2e` (Playwright smoke through every page in demo mode, desktop + phone; needs `npx playwright install chromium` once, or set `PW_CHROMIUM` to an installed Chrome/Edge executable) · `npm run e2e:db` (same against Supabase with `E2E_EMAIL` / `E2E_PW`) · `npm run check` (all of the above) · `npm run deploy` (build and push `dist/` to the `gh-pages` branch).

**Windows:** `setup.ps1` (next to this README) does the whole first-time setup — checks Node ≥ 20, extracts the zip, creates `.env`, installs packages and the Playwright browser, runs `npm run check`, then starts `npm run dev` in its own window and opens the app. `powershell -ExecutionPolicy Bypass -File setup.ps1 -Zip "<path to zip>"`. Keep the project **outside OneDrive** (the script defaults to `C:\Users\<you>\CascadeProjects\wealthpilot`): `node_modules` has tens of thousands of files and OneDrive sync fights with `npm install`.

## Deploy (GitHub Pages)

1. Create a repo (e.g. `wealthpilot`), push this folder.
2. `npm run deploy` publishes `dist/` to `gh-pages`. In the repo settings choose Pages → branch `gh-pages`.
3. The app is then at `https://<user>.github.io/wealthpilot/` — live: **https://garynth41.github.io/wealthpilot/**. `vite.config.ts` uses `base: './'` and the router uses hashes, so no path configuration is needed.
4. In Supabase → Authentication → URL configuration, add that URL to **Site URL / Redirect URLs** (for confirmation and password-reset links).

## Email capture setup (optional)

- **Gmail:** Google Cloud → APIs & Services → enable *Gmail API* → Credentials → OAuth client (Web application) → add your site origin to *Authorized JavaScript origins*. Paste the client ID in **Settings → General → Email capture** (or Email Money Capture → Set up Gmail). Scope: `gmail.readonly`.
- **Outlook:** Entra admin → App registrations → *Single-page application* with redirect URI `https://<your-site>/` → API permissions `User.Read`, `Mail.Read` (delegated). Paste the Application (client) ID in **Settings → General → Email capture**; tenant `consumers` for personal outlook.com.
- Nothing is sent, labelled or deleted. Bodies are never stored.

## Members, access and invitations

Owners manage people under **Settings → Members**. Each member has one of four access levels:

| Level | Can see | Can change |
|---|---|---|
| **Owner** | everything | everything, plus members, settings and categories |
| **Full access** | everything | everything except members/settings |
| **Read-only** | everything | nothing |
| **Limited** | only the sections ticked (Transactions & insights, Budget, Bills, Income, Accounts & debts, Bank connections & email, Investments, Tax, Goals, Hardship) | those sections, or nothing if read-only |

Dashboard, Reports and Settings are always available and only show what the member can already see. The map lives in `src/lib/access.ts` (`MODULES`) and the database enforces the same map with row-level security (`module_allowed` in `supabase/migrations/0003_member_access.sql`) — a limited member's API calls cannot read other sections' tables at all.

**Inviting someone** creates their sign-in with a one-time temporary password (`WP-xxxx-xxxx-xxxx`) and drafts the invitation email for you, with Copy and *Open in email app* buttons. The password is shown once and never stored. On their first sign-in they must choose their own password (10+ characters, mixed case, a number, not the temporary one) before any data is shown. Someone who already has an account is simply added, and the email tells them to use their existing password.

This runs in the `invite-member` edge function (`supabase/functions/invite-member/`), deployed with `supabase functions deploy invite-member` (or the Supabase MCP). To send invitations automatically, set the function secrets `RESEND_API_KEY` and `INVITE_FROM` (`WealthPilot <invites@yourdomain>`); without them the app shows the drafted email for you to send. Set `VITE_SITE_URL` in `.env` so the email links to the deployed site rather than the page you are on.

## Conventions

- Money is `numeric` in Postgres and `number` in TS; amounts on transactions are always **positive** — `kind` (+ accounts) gives direction.
- Dates are `YYYY-MM-DD` strings in local time; `today()` can be frozen with `setToday()` for tests.
- Budget actuals are **never stored** — they are computed from transactions for the period's date range. A budget line only holds the plan (+ rollover).
- Every write goes through the store (`insert / update / remove`), which is optimistic and falls back to the Repo; transactions post to balances via `lib/ledger.ts`.
- Pages never talk to Supabase directly.
