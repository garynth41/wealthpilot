# The phone apps (iPhone and Android)

Since 0.25.1 Cresari also ships as an iPhone app and an Android app. They are the **same web app** (`dist/`, the build that runs at
https://garynth41.github.io/wealthpilot/), wrapped with [Capacitor 8](https://capacitorjs.com/) and pointed at the production database.
One account and one household work everywhere. Getting them into the stores, step by step, is in [STORE_LAUNCH.md](STORE_LAUNCH.md).

| | |
|---|---|
| App ID (both stores, permanent once published) | `com.cresari.app` |
| Name on the home screen | Cresari |
| iOS | iPhone only, iOS 15+, Swift Package Manager (no CocoaPods), built with Xcode 26 |
| Android | Android 7+ (minSdk 24), targets Android 16 (SDK 36), JDK 21 |
| Version | from `package.json`: 0.25.3 → version name 0.25.3, Android versionCode and store iOS build number 250300 (a rebuild adds 1; a local Xcode run shows build 1) |

## What is different inside the apps

Everything that behaves differently goes through `src/app/native.ts`; pages never check the platform themselves.

- **Files** — exports (backups, CSV, Excel, attachments, recovery codes) open the share sheet (Save to Files / Drive, Mail, AirDrop…) instead of downloading.
- **Links to other sites** open in the system browser, never inside the app. Policy pages (`publicUrl()`) always point at the website.
- **Sign-up, password-reset and invitation links** use the website address (`SITE_URL` in `src/app/config.ts`): the app's own address is `capacitor://localhost` (iOS) or `https://localhost` (Android), which an email cannot open.
- **Android Back button** closes the top dialog, then goes back a page, then leaves the app from the Dashboard.
- **Status and navigation bars** follow the light/dark theme (`syncSystemBars`); the layout pads for notches with `env(safe-area-inset-*)`.
- **Idle lock** offers Face ID / Touch ID / fingerprint (`@capgo/capacitor-native-biometric`), with the password as the alternative.
- **Bill reminders** are scheduled on the phone (`src/lib/reminders.ts` decides what and when; `src/app/nativeReminders.ts` schedules
  them) instead of web push. Android alarms are deliberately *inexact*, so the app never asks for the "Alarms & reminders" permission.
- **No service worker** (the app already has its files), **no passkeys** (they need the website's domain), **no Gmail/Outlook capture**
  (Google and Microsoft block sign-in inside apps) and **no print-to-PDF** (Excel and CSV instead). The screens say so where it matters.
- **Updates** — the website updates itself; the apps update from the stores. `app_meta.latest_native_version` shows an "update available"
  banner; `app_meta.min_native_version` blocks older apps with a full-screen "Update required" notice (only for changes an old app
  would break, such as a database change). Set them only after the version is live in both the App Store and Google Play:
  `update public.app_meta set value = '0.25.3' where key = 'latest_native_version';`
- **Fonts** are part of the app (`src/fonts.css`, generated by `npm run fonts` from the @fontsource packages) — no request to Google, and
  they work offline.

## Files

| Path | What |
|---|---|
| `capacitor.config.ts` | app ID, name, colors, splash, system bars, notification icon |
| `android/` | the Android Studio project (committed; `app/src/main/assets/public` is generated and ignored) |
| `ios/` | the Xcode project (committed; `App/App/public` is generated and ignored). `App/App/PrivacyInfo.xcprivacy` is the privacy manifest |
| `assets/` | icon and splash sources, drawn by `scripts/native-assets.mjs` |
| `store/` | store listing text (`listing/`), screenshots (`screenshots/`), feature graphic |
| `public/{privacy,terms,support,delete-account}.html` | the pages both stores link to |
| `scripts/play-upload.mjs` | uploads an Android bundle to Google Play (used by the release workflow) |
| `scripts/store-shots.mjs` | draws the store screenshots from the demo |

## Everyday commands

```bash
npm run native:sync            # build the web app and copy it into android/ and ios/ (run after any web change)
npm run native:sync -- android # just one platform
npm run native:assets          # redraw icons, splash screens, notification icon and the Play feature graphic
npm run build && npm run store:shots   # redraw the store screenshots (store/screenshots/)
npm run fonts                  # regenerate src/fonts.css after changing a weight in scripts/fonts.mjs
```

**Android on your own phone, today:** every CI run keeps a debug build. On GitHub open **Actions → ci → the latest run → Artifacts →
android-debug-apk**, unzip it on the phone, open `app-debug.apk` and allow installing from that source. (A debug build and a store build
are signed differently, so one cannot be installed over the other — uninstall the first.)

**Android Studio:** open the `android/` folder (Android Studio Otter or later, JDK 21). Run on an emulator or a phone with USB debugging.

**Xcode** (needs a Mac): open `ios/App/App.xcodeproj` in Xcode 26+, pick your team under Signing & Capabilities, run on a simulator or an
iPhone. Without a Mac, CI builds it (below) and TestFlight puts it on your iPhone.

## CI and releases

- **Every push and pull request** (`.github/workflows/ci.yml`): besides the web checks, the `android` job makes a debug build and the `ios`
  job a simulator build (unsigned) on macOS 26. They catch a broken native project or plugin; they never hold up the website deploy.
  Dependabot updates only merge themselves once both phone builds pass.
- **Store builds** (`.github/workflows/release-apps.yml`, run by hand from the Actions tab): a signed Android App Bundle (kept on the run,
  and sent to Google Play as a draft when connected) and an iOS build uploaded to App Store Connect / TestFlight. Inputs: which platform,
  the Google Play track, and a **rebuild** number (0–99) for uploading the same version again. Secrets and how to make them:
  [STORE_LAUNCH.md](STORE_LAUNCH.md#secrets).
- **Version numbers:** every store upload needs a new number. Raise the version in `package.json` (as every release already does), or
  run the workflow with rebuild 1, 2, … for the same version. Android versionCode = iOS build number = major × 1,000,000 + minor × 10,000
  + patch × 100 + rebuild.
- **iOS signing** needs no certificates in the repo or on a Mac: the archive is built unsigned and the App Store Connect API key signs the
  export with Apple's cloud-managed distribution certificate (signing the archive itself would create a new development certificate on
  every run until the team's limit is reached).

## Updating Capacitor or a plugin

`npm install @capacitor/…@latest`, then `npm run native:sync`, and commit whatever changed under `android/` and `ios/`. CI's phone builds
confirm it. Check the plugin's release notes for new permissions (Android merges plugin permissions into the app: run
`aapt2 dump badging app-debug.apk | grep permission` and compare with the list in STORE_LAUNCH.md's Data safety section).

## Things to keep in step

- A new kind of data the app keeps → update the privacy policy (`public/privacy.html`), the App Privacy answers and
  `ios/App/App/PrivacyInfo.xcprivacy`, and the Play Data safety form (STORE_LAUNCH.md has the current answers).
- A new permission (camera, location, contacts…) → an iOS usage string in `ios/App/App/Info.plist`, and the Play permission declarations.
- New external sites the app talks to → the Content-Security-Policy in `index.html`.
